# Фронтенд — общие правила разработки

Свод правил для фронтенд-кода по проектам Callibri и смежным сервисам.
Читай этот файл при любой задаче, которая затрагивает UI, React/TypeScript, Web Components,
стили, точки входа сборки или данные из Rails/бэкенда в JS.

Пометки в тексте: **блокер** — нельзя мержить; **флаг** — требует обсуждения на ревью.

Ориентир по плотности и тону — соседние `docs/frontend.md` в репозиториях. Локальные
ограничения конкретного репо (пути, имена entry, конфиги линтера) **важнее** общих правил:
сначала соседний код и локальный `docs/frontend.md`, затем этот файл.

---

## Когда что применять

| Тип проекта | Типичный стек | Где смотреть локально |
| ----------- | ------------- | --------------------- |
| Кабинет / SPA (React) | React 18+, TypeScript strict, CSS Modules, Vite или ESBuild | `webpack/src/`, `app/javascript/` |
| UI-библиотека | React, Storybook, токены, named exports | `src/ui/`, `src/components/` |
| Web Components | TypeScript, custom elements, Shadow DOM, Webpack | `js/widget/`, слой custom elements |
| Legacy | jQuery / plain JS / Sprockets / SCSS | `app/assets/` |
| Почта / без браузерного UI | HTML mailer | только шаблоны писем |

Новый продуктовый UI по умолчанию — в React/TS (или Web Components, если так устроен слой).
Новый функционал на jQuery при наличии React-слоя → **флаг**, уточни причину.

## Общие принципы (все конвейеры)

1. **Сначала сосед.** Нейминг, структура папок, плотность комментариев и границы слоёв — как
   у соседнего кода той же зоны. Не вводи новую систему именования или новый стек «на всякий случай».
2. **Baseline Widely available.** В CSS, HTML, JS и Web API — только возможности со статусом
   Baseline Widely available (MDN / web.dev/baseline). Newly available и Limited availability
   не применяй: в браузерах без поддержки код часто молча не работает.
3. **Комментарии — на русском**, в стиле окружающего файла. JSDoc у сервисов, API и хуков с
   нетривиальной логикой (`@param`, `@returns`); у UI — короткое описание над экспортом.
4. **Осмысленные имена.** `data`, `val`, `obj`, `arr`, `tmp`, `foo` → флаг.
   Исключения: `e` / `event` для события, `i` / `j` для индекса цикла.
5. **Не смешивай конвейеры** без явного моста. React ↔ jQuery только через согласованный
   `window.*` / JSON-данные / DOM-контракт → иначе флаг.
6. **Cleanup обязателен.** React: `useEffect` с подписками — с cleanup. jQuery / DOM: снятие
   обработчиков (`.off()` / `removeEventListener`) при удалении элемента. Иначе → флаг.
7. **Мобильная вёрстка.** Новый публичный или кабинетный UI без признаков адаптива → флаг
   с рекомендацией проверить на типичных viewport (ориентир: 1920 / 1024 / 375).
8. **Удалённый код.** Вместе с логикой убери связанные стили, точки входа сборки, Sprockets-
   директивы, регистрации packs/entries и мёртвые импорты.
9. **Линтер и форматтер — источник правды.** Лимиты (`max-len`, magic numbers, порядок импортов)
   не дублируй из памяти: сверяйся с `eslint.config.*`, `.prettierrc`, `tsconfig.json` репо.
10. **`eslint-disable` / `@ts-ignore` / `as any`** без краткого обоснования рядом → флаг.

```ts
// eslint-disable-next-line camelcase — данные приходят от API в snake_case
const { user_id } = response;
```

## React + TypeScript

### Стек по умолчанию

- TypeScript **strict**. Обход типизации (`as any`, `@ts-ignore`, `@ts-expect-error`) — только
  с комментарием-обоснованием.
- Type-импорты разделены, если так требует конфиг: `import type { FC }` отдельно от value-импортов.
- Явный тип возврата у компонента там, где это принято в репо (`(props: TProps): JSX.Element`).
- Перед своим UI проверь `@shsh/ui-library` (и локальные `ui/` / `components/`): не форкай
  примитив в потребитель, если его место в библиотеке.
- `===`, без `eval` (`eval` → **блокер**). Без вложенных тернарников и глубокой вложенности
  колбэков — лимиты в ESLint репо.
- Guard clauses / ранние `return` вместо глубокой вложенности `if/else`.
- `const` по умолчанию; `let` только при переприсваивании. `var` в новом коде → флаг
  (исключение — осознанный legacy-слой со своим стилем).

### Анатомия компонента

Ориентир — соседние компоненты репо, не абстрактный «идеальный» шаблон. Типичная папка:

```
MyComponent/
  index.tsx                     — публичный API / реэкспорт
  MyComponent.container.tsx     — логика, хуки, запросы (если нужно)
  MyComponent.view.tsx          — чистая презентация
  MyComponent.service.ts        — чистые утилиты, преобразования, валидация (без JSX и хуков)
  MyComponent.types.ts          — типы (если не локальны в одном файле)
  MyComponent.config.ts         — константы, магические числа, конфиг секции
  MyComponent.module.scss       — стили (CSS Modules)
  MyComponent.test.tsx          — тесты (если приняты в репо)
  MyComponent.stories.tsx       — stories (для ui-library)
```

- Новый компонент с хуками/запросами/побочными эффектами без Container/View → флаг.
  **Исключение:** умещается в ~50 строк, без хуков/запросов/эффектов — один `index.tsx`.
- Логика во вьюхе (хуки, запросы, бизнес-правила) → флаг. Вьюха принимает props и рендерит.
- Пропсы без интерфейса / типа → флаг.
- В ui-library: именованный экспорт + `displayName`; **`export default` не использовать**.
- Тип, нужный только в одном файле, не обязан жить в `.types.ts`. Вынос оправдан, когда тип
  шарится или интерфейс пропсов большой (ориентир: > 5 полей).

### Порядок тела компонента

Между частями — пустая строка; отсутствующие части пропускай. Все хуки — **до** ранних `return`.

1. Константы из хуков без деструктуризации (`useAppDispatch`, `useQueryClient`, …).
2. Деструктуризация результатов хуков (`useToaster`, `useModal`, …).
3. Состояние из стора (`useAppSelector` / аналог).
4. Локальный `useState`.
5. Остальные константы.
6. Деструктуризация объектов и массивов.
7. `useEffect`.
8. Запросы и мутации (`useQuery`, `useMutation`, thunks).
9. `useCallback` и обработчики.
10. Ранние `return`.
11. Основной `return` с JSX.

```tsx
const dispatch = useAppDispatch();
const queryClient = useQueryClient();

const { showError } = useToaster();
const { openModal, closeActiveModal } = useModal();

const paths = useAppSelector((state) => state.paths);

const [activeOverrides, setActiveOverrides] = useState<Record<number, boolean>>({});

const pathCount = Object.keys(paths).length;

useEffect(() => {
  document.title = window.location.pathname;
}, []);

const { data } = useSomeData();
const { mutate } = useMutation({});

const handleClick = useCallback(() => openModal(), [openModal]);

if (!paths) {
  return null;
}

return <div>{data}</div>;
```

### Импорты и алиасы

- Глубокие `../../../` → флаг. Используй алиасы из `tsconfig` / Vite / Webpack.
- Новый алиас регистрируй во **всех** местах, где он заведён в репо (часто: `tsconfig`,
  `vite.config` / `webpack.config`, иногда Jest).
- Порядок импортов задаёт Prettier/плагин репо — не расставляй руками вразрез с конфигом.
  Типичный порядок:
  1. `react`
  2. сторонние библиотеки
  3. `@components` / `@ui` / `@layout` / `@pages`
  4. `@store` / `@redux` / `@api` / `@hooks` / `@utils` / `@assets`
  5. локальные (`.view`, `.container`, `.service`, `.types`, `.module.scss`)

### DOM `id` для интерактива

Интерактивным элементам задавай осмысленные стабильные `id`. Переиспользуемый контрол получает
обязательный `id` через пропсы и суффиксы по назначению: `${id}-submit-button`, `${id}-email`.
В списках — постоянный ключ записи, иначе индекс. Не используй случайные значения, `useId()`
или эфемерные client-key для DOM-идентификаторов, если в репо принят явный `id`-контракт.

## Состояние загрузки, запросы, ошибки

### Парность лоадера — блокер

Любой показ глобального/экранного лоадера без парного скрытия на **всех** ветках, включая ошибки →
**блокер** (интерфейс зависает в состоянии загрузки).

- Старт — до `try` / цепочки промисов; завершение — в `finally`, не только в `catch`.
- Строго один «выкл» на один «вкл», если в сторе счётчик активных лоадеров.
- То же для legacy: `showBlockUI` / `showLoader` ↔ `unblockUI` / `hideLoader`.

### Три состояния данных

Загрузка, пустой ответ и ошибка — **разные** состояния UI. Не оставляй лоадер после ошибки
и не показывай «пусто» там, где была ошибка сети.

### HTTP-клиент

Не плоди новые `axios.create` / обёртки, если в проекте уже есть инстансы с refresh, CSRF и
обработкой ошибок. Допиши вызов в существующий слой API / thunks / services.

### Redux / стор

- Типизированные хуки (`useAppDispatch` / `useAppSelector`) вместо «сырых» `useDispatch` /
  `useSelector`, если они есть в репо → иначе флаг.
- Новый слайс подключай в store.
- Меняешь форму данных в `redux-persist` — пиши миграцию по схеме репо (отдельный `version_N.ts`,
  снапшот данных внутри файла, без импорта живого runtime-конфига). Бамп версии без `migrate`
  молча вытирает пользовательские настройки → **блокер** по смыслу данных.

## Стили

### CSS Modules

- Стили компонента — `ComponentName.module.scss` + `className={styles.container}`.
- Глобальный `.css` / `.scss` «на компонент» или `className="container"` строкой → флаг.
- Нет изоляции стилей страницы в legacy → флаг (префикс/`[data-page]`/класс-обёртка).
- Вложенность селекторов > 4 уровней → флаг.
- `!important` без комментария с обоснованием → флаг. Допустим для перебивки инлайн-стилей
  и сторонних библиотек.

### Токены и цвета

- Цвета, отступы, типографика — из дизайн-токенов (`@shsh/ui-library`, `root.scss`, `vars.scss`
  проекта). Хардкод hex/rgb или локальная SCSS-переменная с цветом → флаг.
- Цвета, которого нет в палитре, в приложении не заводи — добавляй в ui-library (витрина
  Storybook **STYLES/Variables**).
- Полупрозрачность: предпочтительно токены opacity / `color-mix(in srgb, var(--X) N%, transparent)`.
  Относительный `rgb(from var(--X) r g b / N%)` не используй, пока он не Baseline Widely available
  в вашем стандарте: в старых браузерах цвет молча пропадает.
- Тема — через `data-theme` / принятый в репо механизм; тёмные значения только там, где отличаются
  от светлых.

### Адаптив

- Брейкпоинты и миксины бери из проекта (`$sm` / `$md` / `$lg`, `minContentWidth` и т.п.).
- Для раскладки кабинета учитывай сайдбар: обычный `@media (min-width: $lg)` может врать —
  смотри локальный миксин.
- Новый UI с раздельными desktop/mobile ветками — проверь обе.

## Иконки

- **Разметку SVG в JSX не держи** без крайней нужды. Иконка — файл `.svg`, подключение через
  принятый в репо способ (`SvgIcon`, named `*Icon` из ui-library, url на файл).
- Общего назначения — в `@shsh/ui-library` (`src/ui/Icon/svg/`), не копируй в каждый кабинет.
- Не править руками сгенерированные артефакты иконок (`Icon.named.tsx`, `Classes.module.scss` и т.п.).
- Цвета состояний (hover / active / disabled) — CSS-переменными снаружи, не пропсами внутрь
  `<use>`, если так устроен `SvgIcon` проекта.
- Учитывай ограничение origin для внешних `<use href="…svg#icon">`: вынос ассетов на чужой CDN
  без прокси ломает иконки разом.

## Точки входа и данные из бэкенда

### Регистрация entry

Новый pack / `vite_pack_tag` / webpack entry без записи в манифест/конфиг репо → **блокер**:
приложение не подключится. Руками легко забыть половину — используй генератор страницы, если он есть.

Конфликт в закоммиченных артефактах сборки (`manifest.json`, чанки) руками не «лечи» → **блокер**:
пересобери от актуального master/основной ветки по процессу репо.

### Данные Rails → JS

Данные из Ruby в JS/ERB без экранирования → **блокер** (XSS):

```erb
var name = "<%= @user.name %>";                      <!-- блокер -->
var name = "<%= escape_javascript(@user.name) %>";   <!-- правильно, можно j() -->
const state = <%== @initial_state.to_json %>;        <!-- допустимый паттерн, если так в репо -->
```

Предпочтительные каналы:

- `react_component` / `@props`;
- `<script type="application/json" id="__REACT_DATA__">` (или `__REACT_CONTEXT__` / `__REACT_PATHS__`);
- data-атрибуты / `<meta>`;
- `content_tag` + `to_json`.

Не используй `<%= raw @data %>` и произвольную логику «на десяток строк» в инлайн-`<script>` —
выноси в файл ассетов/entry → иначе флаг.

Новое поле в JSON-контракте описывай синхронно: Rails + TypeScript-типы (+ сериализатор/операция).

### CSRF и секреты

- CSRF-токен не уходит в API-запросы к своему Rails → **блокер** (для axios — настройка инстанса;
  для realtime — заголовок, принятый в репо).
- Токены, ключи CDN, pairing-секреты, `devices.json` — не в git и не в логи.
- Не ослабляй auth / CSRF / Host-checks / HMAC «для удобства» без явного запроса и фиксации риска.

## Web Components

- UI собирается из custom elements (`extends HTMLElement`); регистрация — через принятый в репо
  хелпер (`registerWebComponent` / `createWebComponent` или аналог), тег с единым префиксом владельца.
- Слои: `components/` (только элементы), `services/` (доменная логика), `utils/` (чистые хелперы),
  `store/` (состояние экземпляра), если такая раскладка уже есть.
- Данные parent → child: `externalData` + `get/set data`. Внутри читай `this.externalData`.
- Если нужен live-preview при смене настроек — реализуй частичный/полный `updatePreview` по
  паттерну соседа; правки общего слоя проверяй на всех entry, которые его используют.
- Стили компонента — в Shadow DOM (`attachShadow({ mode: "open" })`), CSS-переменные с префиксом
  владельца. Новый UI без shadow — только если сосед того же типа так сделан.
- Не оборачивай всё приложение в один mega shadow-root / внешний CSS-wrapper, если продукт
  это запрещает (ломает интеграции на чужих страницах).
- Строки UI — через i18n/словари, не хардкодом в разметке.
- Глобалы хоста типизируй явно, не через неявный `any`.

## Legacy (jQuery / Sprockets)

- Новый JS/SCSS в корне `app/assets/...` без тематической подпапки → флаг.
- Дублирование `//= require` уже подключённой в манифесте библиотеки → флаг.
- Файл вне манифеста, подключаемый `javascript_include_tag` / `stylesheet_link_tag`, обязан
  попасть в precompile-список репо → иначе **блокер** на проде.
- Изменён исходник Grunt/минификации без обновления артефактов (если репо коммитит артефакты) →
  **блокер**.
- `var self = this` — там, где это конвенция legacy-слоя.
- Захардкоженные URL: смотри стиль репо (в одних — флаг и data-атрибуты из Rails, в других —
  относительные пути норма). Не навязывай чужой репо паттерн кабинета.

## Тесты

- Новый чистый хелпер / сервис — с соседним `*.test.ts(x)`, если так принято в репо.
- Поведение компонентов — React Testing Library; селекторы ближе к пользователю, не к внутренностям.
- Описания `it` / `describe` — на русском, как в существующих тестах.
- Не гоняй весь suite локально без нужды — точечно по изменённому; полный прогон делает CI
  (если фронт в CI есть; иначе — pre-commit / ручной `yarn test && yarn lint`).
- Pixel / forms / e2e: новую страницу регистрируй в конфиге репо; эталоны коммить осознанно;
  динамику отключай флагами вроде `isVisualPageTest`, если они есть.
- Покрытие ui-library — ориентир ≥ 80% (см. локальный `TESTING.md`).

Типичные команды (уточняй по README репо):

```bash
yarn lint
yarn prettier          # или npx prettier --check …
yarn test path/to/file.test.tsx
yarn build             # при сомнении в entry/алиасах/иконках
```

## Безопасность (фронтовый контур)

- XSS из ERB/инлайна → **блокер** (см. выше).
- CSRF на мутирующих запросах к своему бэкенду → **блокер**.
- Не клади секреты в клиентский бандл «навсегда»: всё в `import.meta.env` / `process.env`,
  что попадает в браузер, считай публичным. В Vite из `process.env` часто доступен только
  то, что явно прокинуто `define` — остальное будет `undefined` → флаг.
- `postMessage` / storage родителя из iframe — только через принятые хелперы и проверку origin,
  как в существующем коде (не расширяй произвольным `*`).
- Ошибки пользователя — через принятый канал (toastr / toaster / ErrorBoundary), без утечки
  внутренних стеков и токенов в UI.

## Что не делать

| Действие | Статус |
| -------- | ------ |
| `eval`, непроверенный HTML из пользователя/Rails без escape | **блокер** |
| Лоадер без парного скрытия на ошибке | **блокер** |
| Новый entry без регистрации в конфиге сборки | **блокер** |
| Ручной «фикс» конфликтов в production-чанках/manifest | **блокер** |
| Бамп redux-persist version без migrate | **блокер** по данным |
| Новый продуктовый UI на jQuery при наличии React-слоя | флаг |
| Хардкод цвета вместо токена | флаг |
| Глубокие relative-импорты вместо алиаса | флаг |
| `eslint-disable` / `as any` без комментария | флаг |
| Вечный слушатель без cleanup | флаг |
| Неинформативные имена переменных | флаг |
| Логика в `.view.tsx` | флаг |
| Инлайн-SVG иконки «просто так» | флаг |
| Свой axios/refresh рядом с готовым слоем | флаг |
| `export default` в ui-library | флаг |
| Переформатирование чужого legacy-файла «заодно» | флаг (шумный дифф) |

## Чек-лист перед завершением фронтовой задачи

1. ✅ Соседний код и локальный `docs/frontend.md` / `AGENTS.md` учтены.
2. ✅ Компонент лежит папкой с нужными `*.module.scss` / types / service / container-view.
